# Step 7A — Assignment, deletion, and self-unassign

**Status:** Implemented locally; migration not yet applied.

- Add `assign_task_people(...)`, a narrow definer changing only primary/assist arrays. Active Admins and active Co-Admins may use it only when they have `real` access to the task. Validate ids, activity/new-assignee rule, duplicates, the combined 100-person maximum, and existing-inactive retention. A no-op has stable SQLSTATE `CCN01`. Removing the final primary applies the shared safe `To Do` tail reset only when the stored status is neither `To Do` nor `Completed`; an already-`To Do` task keeps its rank, and a Completed task keeps its status and rank.
- Add `delete_task(...)` for active Admins/Co-Admins with `real` task access. Delete only a stored `To Do` task; reject prerequisites and deletion leaving an Active event empty. Confirmation stays in a modal; no drag-delete. Deferred tests force constraints immediate.
- Add `unassign_self(...)`, deriving `auth.uid()` and removing only that id. The owner-confirmed cutoff remains 72 hours: a null due date is allowed, while a non-null due time must be more than the named 72-hour constant away. Inside the cutoff or overdue, direct the caller to ask an Admin or Co-Admin. Completed tasks have their own rejection. If the final primary leaves an In Progress task, use the same shared `To Do` tail reset as assignment; an already-`To Do` task keeps its rank. Warn when confidential access will be lost and log actor/time exactly once.
- These functions use Step 7's migration-owner branch, expanded to exactly `status`, `sort_order`, `depends_on_task_id`, `primary_assignees`, and `assist_assignees`. `assign_task_people` and `unassign_self` share one ungranted invoker-security reset helper and use event-row/advisory/task lock order. Cross-committee management remains inside real-access-gated named operations; general edit remains own-committee. Creator grants no right. Do not broaden raw update/delete or add a general board endpoint.
- **Database impact:** narrow primary/assist writes; `delete_task` deletes one row. New migration: **yes**, for three functions/grants. Raw policies unchanged.
- **Guards that must remain true:** Archived parents reject writes; delete preserves dependency and Active-event invariants; self-unassign changes no one else, respects cutoff, logs once, and never changes event id.
- **Security risks:** re-read caller/activity, real task access, stored status/due/assignments/dependents/parent; validate arrays; check exact counts. Masked tasks expose no controls. Cross-committee rights remain inside named operations and the shared guard branch.
- **Test deliverable:** `docs/PHASE-4-STEP-7A-TESTS.md` follows the global contract and proves real versus masked cross-committee management, prerequisite/last-task blocks, no-op and Completed behavior, self-unassign timing/Backlog/activity/access-loss, exhausted-rank collision safety, event-id immutability, Archived denial, unchanged general scope, the five owner-branch writers, the ungranted reset helper, and the nine-function full direct-writer set.
- **Acceptance:** approved managers assign/unassign/delete without general rights; protected/last tasks cannot delete; self-unassign follows due/access rules, restores Backlog when needed, logs actor/time; creator has no effect.
