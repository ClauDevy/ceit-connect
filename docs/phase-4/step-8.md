# Step 8 — Backlog claim, self-service assistance, and workload

**Status:** Originally optional; selected, merged, verified, and live on Dev and Prod. Step 8A contains the database contracts and Step 8B contains the UI.

- Step 8B adds Claim buttons to real Backlog cards, caller-session backup and volunteer controls on task detail, workload labels in leadership assignment pickers, and a paginated Help Wanted surface at `/workspace`. The navigation label is **Tasks** so Step 9A can add the personal My Tasks feed beside Help Wanted without another route or navigation rename.

- Add `claim_task(...)`: any active Admin, Co-Admin, or Member from any committee may claim an unassigned Backlog task. The function derives the claimant from `auth.uid()`, locks and re-reads the task, requires no primary assignees at lock time, and adds the caller exactly once. There is no per-user task limit. Reject Draft and Archived tasks and make concurrent claims deterministic.
- Show safe workload counts in leadership assignee pickers, such as “Maria — 4 active tasks,” through a restricted aggregate function. Return only active users already available to the picker and counts of non-Completed primary/assist assignments; never return task titles or other task content.
- Request or cancel Backup may be called by a current primary assignee, active Admin, or any active Co-Admin. Add `task_volunteers(task_id, user_id, created_at)` for pending offers. Any active user may volunteer where the restricted Help Wanted response permits it and may withdraw their own offer before acceptance.
- Accepting a volunteer is allowed to an active Admin, any active Co-Admin, or any current primary assignee of that task—never because of `tasks.created_by`. Acceptance transactionally re-checks the task and volunteer, deletes the pending offer, and adds the still-active volunteer exactly once to `assist_assignees`. No notification is sent in Phase 4.
- Serve Help Wanted through a restricted, fixed-shape RPC; do not restore the raw `request_backup` read path removed in Step 1A. It requires an active caller and returns only the fields authorized for that caller, preserving confidential masking.
- **Database impact:** narrowly updates `tasks.primary_assignees`, `tasks.assist_assignees`, and `tasks.request_backup`; adds `task_volunteers` with indexes, RLS, and an Archived-parent write guard; adds workload, Help Wanted, claim, request/cancel, volunteer/withdraw, and accept functions. New migration: **yes**. Raw `tasks`/`users` selects remain unchanged.
- **Guards that must remain true:** no claim, backup, volunteer, withdraw, or accept write occurs for Archived tasks; Draft tasks never become council-wide Help Wanted; confidential responses stay masked unless the caller currently has real access; assignment changes do not alter task event, dependency, status, or count; `created_by` grants nothing.
- **Security risks:** re-read task state and derive every actor; do not trust task, user, role, assignment, or volunteer ids from the client. Prevent duplicate array entries/offers, validate volunteer activity again at acceptance, serialize claim/accept races, return only safe aggregate/profile fields, check every database error and affected-row count, and keep child rows frozen under Archived parents.
- **Test deliverable:** `docs/PHASE-4-STEP-8-TESTS.md` follows the global test contract and covers every required role, cross-committee and unlimited claims, concurrent claims, the request/cancel role matrix, safe Help Wanted output, volunteer/withdraw/accept flows, duplicate and inactive-user races, confidential masking, child-table archive freeze, and Draft/Archived denials.
- **Acceptance:** any active user can claim an unassigned Active-event Backlog task regardless of committee and may claim multiple tasks; only approved actors request/cancel backup or accept a volunteer; volunteers may withdraw before acceptance; acceptance creates one assist assignment; workload counts are correct without content leakage; Step 1A raw-read protections remain intact; no notification row is created.
