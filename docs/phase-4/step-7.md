# Step 7 — Dependencies and confidentiality controls

**Status:** Gate-critical.

- Do not add a second general writer beside `edit_event_with_tasks`. General task fields remain in Event Edit with Admin/all-task and Co-Admin/own-committee scope. Board/modal exposes only this step's narrow actions and optional Step 7A.
- Add `set_task_dependency(...)` as a narrow `SECURITY DEFINER` function because all active Co-Admins may change one dependency across committees. It changes only `depends_on_task_id`, re-reads both tasks, requires same event, rejects self/cycles, permits clear, and never changes status. Step 5a continues to block prerequisite deletion.
- Add a narrow confidentiality function changing only `is_confidential/allowed_viewers`. It may remain `SECURITY INVOKER` because active Admin/owning-Co-Admin scope already matches RLS, but still performs explicit active-role/column checks. Viewers may be active users from any committee through the safe picker. Validate existence/activity, duplicates, and a documented maximum server-side.
- Default definer design matches Step 5b: own cross-committee narrow functions with the migration owner, use fixed empty `search_path`, derive `auth.uid()`, explicitly verify active Admin/Co-Admin, grant only `authenticated`, and extend the assignee guard's single migration-owner branch only to the exact dependency/assignee columns needed by Steps 7/7A. Each function remains limited to its named concern; the independent archive guard is never exempted. `delete_task` needs no update exemption.
- **Fallback only:** if this migration-owner design fails the complete function-body, direct-SQL, guard, ownership, and privilege tests, use one dedicated minimal `NOLOGIN` narrow-action owner separate from the move fallback. The hosted managed `postgres` role used to apply migrations can create `BYPASSRLS` roles, but grant that attribute only if required. Remove creator self-membership; grant no gateway/service membership; assert no direct/transitive path, false `pg_has_role` membership/usage, and failed `SET ROLE` from `anon`/`authenticated`. Step 7A uses whichever design Step 7 proves.
- Access-list UI is visible only to real-content viewers. Changes affect task/comment/work-link access immediately. Archived tasks never allow `is_confidential/allowed_viewers` writes; existing allowed read paths remain.
- All-Co-Admin dependency permission is an intentional narrow exception; `edit_event_with_tasks` remains own-committee for general Co-Admin edits. Do not broaden raw update/delete. Step 7 does not replace or overload the edit RPC.
- **Database impact:** narrow writes to `depends_on_task_id`, `is_confidential`, and `allowed_viewers`; adds two narrow functions/grants and shared access-helper updates. New migration: **yes**. Raw RLS remains committee-scoped.
- **Guards that must remain true:** Archived parents reject both functions; Draft remains leadership-only; dependencies stay same-event/no-self/no-cycle; archive confidentiality freeze is absolute; `event_id` is immutable; creator grants nothing.
- **Security risks:** accept only necessary inputs and write named columns. Re-read caller activity/role, task/event/committee, dependency graph, and viewers. Check affected counts, fixed path, exact owner/grants/guard branch; forbid JSON patching and audit every migration-owner definer that can write tasks.
- **Test deliverable:** `docs/PHASE-4-STEP-7-TESTS.md` follows the global contract and proves all-Co-Admin dependency versus owning-Co-Admin confidentiality, exact migration-owner/security/grants, the single guard branch and column union, narrow-column/event-id immutability, viewer validation/access changes, archive freeze, and no edit-RPC overload. If fallback is used, add the complete owner-isolation and failed-`SET ROLE` suite.
- **Acceptance:** dependency/confidentiality permissions match approved cross-/own-committee rules; general edits remain scoped; invalid dependencies/viewers fail; access changes apply immediately; event id and Archived task fields remain immutable; the default owner design passes or the fallback is test-justified.
