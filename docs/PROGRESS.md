## Decisions log

- Magic link remains the required first login; password and Google are optional extras unlocked after it.
- Gmail SMTP (App Password) is the interim email sender; revisit Resend only if the team buys a domain.
- Invites/user management are Admin-only; users are deactivated, never deleted.
- Dev allows `gmail.com` invites for testing; Prod is meant to end up university-domain-only.
- Phase 3 is built one feature at a time: wire an existing HTML prototype to real Supabase data, test it, then move on.
- Event access deliberately differs from the original spec: Drafts are shared among active Admins/Co-Admins, and any of them may edit or launch a Draft; Members never see Drafts, Active events cannot return to Draft, only Admins may archive/delete, and Archived events cannot be un-archived.
- Event task timestamps use `Asia/Manila` (`UTC+08:00`, no daylight saving) for both form serialization and edit-page display, so browser timezone settings cannot shift saved call/end times.
- Launching requires at least one task; saving a Draft with zero tasks is allowed. Phases are stored on task rows, so empty phases are intentionally not persisted.
- Archive-template imports deliberately honor the caller's existing task RLS: Admins receive all committees, Co-Admins receive only their own committee, and confidential tasks are never returned or copied. Imported confidentiality/viewer rules are therefore reset implicitly because only ordinary non-confidential task structure enters the create form.
- Archiving is permanent and limited to Active events. Incomplete tasks do not block it because task status editing belongs to Phase 4; the Admin confirmation reports the incomplete count, and every task is frozen exactly as stored. Archived events cannot be deleted.
- Git flow: one feature branch per task → CodeRabbit → PR → merge → then push the migration to Prod (the owner does all Supabase CLI pushes).

- Phase 4B officer model: Admin is the SC President title and keeps `committee_id = null`; the `President` lookup row remains. Vice Presidents are Co-Admins. The only officer operations are invite new officer, appoint active Member, return Co-Admin to Member, move Member committee, cancel an unaccepted officer invite, and Admin self-step-down. No Admin may alter another Admin, and the last active Admin is always protected.
- Phase 4B officer caps use private `public.app_settings.enforce_officer_role_caps`, false in Dev and Prod during testing. When enabled under the shared officer lock, active-plus-pending limits are two Admins and one Co-Admin per committee. Existing over-limit accounts remain valid; only new invites, appointments, and activations are checked. Batch 14 must enable the caps through a tracked migration before final release.
- Phase 4B task rules preserve `unassign_self` immediate leave for null deadlines or `due_date > now() + interval '72 hours'`; at/inside the boundary a Member requests leave and may cancel. Authorized leadership can approve/deny at the top of `/workspace` and on task detail. Caps are 10 Draft events per creator, 20 pending leave requests per person, and 20 pending volunteer offers per person.
- Phase 4B event/task decisions: `tasks.updated_at` uses the approved meaningful-row-change semantics; former-member confirmation is `REMOVE <count> MEMBERS`; event deletion uses the event name for one and `DELETE <count> EVENTS` for bulk on one Admin-only Draft/Archived management page with a year filter; metadata-only Edit Event saves remain allowed around completed phases; `Unphased` never completes or locks.
- Phase 4B presentation decisions: whole navigating cards/rows are links without nested controls; phone targets are at least 44px; the phone avatar menu shows full name, role, Settings, and Sign out; per-item destructive actions move into confirmed menus during redesign while bulk/typed-confirmation actions remain buttons; Batch 5 includes restrained route/form/card/list entrance motion; Batch 6 adds no custom link menu.
